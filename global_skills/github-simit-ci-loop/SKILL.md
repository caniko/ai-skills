# GitHub simit CI loop

Use simit as the workflow source of truth and use GitHub pull requests as the
iteration boundary. Keep repository changes and production changes separate.

## Discover first

Inspect before editing:

- `git status`, worktrees, remotes, the default branch, and existing PRs;
- `simit.toml`, the project flake, package/OCI outputs, and tracked workflows;
- the installed simit version and whether the checked-out simit source supports
  the needed provider and Nix installable features;
- workflow permissions, action references, registry inputs, and deployment
  consumers of the image names or digests.

Preserve a dirty worktree. Use a clean worktree or an explicit file list for
the PR. Do not copy unrelated generated or operational changes into it.

## Generate the CI source

Configure the project in `simit.toml`, then generate rather than hand-editing
managed workflows:

```text
simit init ci --platform github --ci-provider actions --runtime nix --check --diff
```

Add workspace flags only when the project needs them. Declare the exact Nix
installables that must be realized, for example:

```toml
[ci]
platform = "github"
provider = "actions"
runtime = "nix"
runner = "ubuntu-latest"
nix_builds = [".#oci-api", ".#oci-worker"]
```

Treat the simit version as part of the input. If it rejects `nix_builds`, do
not silently replace it with `[ci].packages`: package names do not necessarily
select arbitrary flake installables. Fix and test simit on its own PR, then
pin or invoke that revision from the consumer PR before regenerating files.
Likewise, if the renderer omits the required permissions or hosted-runner
shape, fix the renderer and its generated-file test upstream rather than
post-processing the managed workflow.

Generated GitHub workflows must have:

- hosted runners unless self-hosted runners are explicitly requested;
- `permissions: contents: read` unless a step demonstrably needs more;
- immutable action references (commit SHA plus a version comment);
- no registry credentials, deployment tokens, or secret output in build jobs;
- bounded matrix concurrency and no duplicate hand-written equivalent job.

Keep the matrix build-only: `nix build --no-link` catches broken outputs
without silently publishing or deploying anything.

## Make Linux evaluation reproducible

Run the flake on a Linux runner before claiming image readiness. Remove or
replace private SSH-only flake inputs when they are only carrying public pin
data. Never embed credentials or weaken access controls to make evaluation
pass. Keep private cache use optional; a cache miss must remain a normal build
or an explicit, documented failure.

Validate the same artifacts the runner will use:

```text
nix flake check --no-build --no-write-lock-file
simit init ci --platform github --ci-provider actions --runtime nix --check --diff
```

Then run the smallest relevant local formatter and test gate. Do not add
compiler environment overrides to hide a devshell or cross-toolchain bug.

If a hosted run reports `No space left on device`, fix the input that caused
the excess closure first. When the project has a proven runner-disk ceiling,
use simit's `extra_setup` for a bounded ephemeral-runner cleanup and apply the
same setup to the Nix matrix; verify the free-space assumption in the log.
Do not delete repository data or use cluster storage as a workaround.

## Iterate through PRs

Create a draft PR per layer when the provider change and the consumer change
have different owners or failure modes. Stage explicit paths, run
`git diff --cached --check`, push, and wait for all required checks.

Use the GitHub connector for PR metadata when available; use `gh` only when
the connector lacks the needed mutation or returns an integration permission
error. Diagnose a failed run from its actual log:

```text
gh pr checks <number> --repo <owner>/<repo>
gh run view <run-id> --repo <owner>/<repo> --log-failed
```

Fix the smallest root cause, commit it to the same PR branch, and repeat the
exact failing gate. A pending check is not a pass. Do not merge or declare
completion until generated-file drift, local gates, and required hosted checks
are all green.

## Separate build, publication, and deployment

Successful `nix build` proves an artifact can be built, not that the cluster
can pull it. To publish, identify the registry, required credential, image
tag/digest policy, and pull authorization before changing the workflow. If no
authorized credential exists, report the missing secret or upstream owner and
the exact setup and validation commands; do not invent one.

A no-admin path is build-only CI plus a human or existing release job for
publication. GHCR is an alternative only when the repository/package and
cluster pull path are already authorized; switching registries is a separate
deployment change, not a CI workaround.

For a live cluster, run the platform's read-only health check after any
deployment and inspect image digests, readiness, active writer jobs, queues,
and data-availability checks. Do not infer runtime health from GitHub checks.
Keep recovery drills and scheduled writers paused until their required
retained evidence exists.

## Handoff

Report:

1. simit source branch/PR and generated consumer branch/PR;
2. exact local and hosted checks, including failures and fixes;
3. image outputs that built, their publication status, and missing authority;
4. live health evidence and any remaining data-availability gap;
5. the exact next command and upstream producer for every unresolved input.
